## Выбранный путь

Сохраняем единый контракт backend и UI Михаила. Масштаб прогноза — нормализованная мощность выбранных турбин, 0–1, без пересчёта в МВт.

## Действующий контракт

| Операция | Маршрут | Результат для интерфейса |
|---|---|---|
| Готовность | `GET /health` | `status: "ok"` |
| Исходные данные | `GET /measurements?turbine_id=1&limit=100&offset=0` | `original` сохраняет исходные значения CSV |
| Пополнение | `POST /measurements` | Добавление одного измерения; дубль даёт 409 |
| Загрузка CSV | `POST /measurements/upload?turbine_id=1`, multipart `file` | Число проверенных, добавленных и повторных строк |
| Турбины | `GET /turbines`, `POST /turbines` | Координаты, название и необязательная ссылка Google Maps |
| Обучение и ревизии | `POST /models/train`, `GET /models` | Новая ревизия, MAE, охват обучения; артефакт хранится в БД |
| Расчёт | `POST /forecasts/{issue_date}` с `turbine_ids` и `revision_id` | `id`, `status`, `analysis`; 48 часов на выбранную турбину |
| Просмотр | `GET /forecasts/{id}` | `issued_at`, `weather_run_at`, `model_version`, точки выбранных турбин |

Фронтенд посылает дату в формате `YYYY-MM-DD`, ID выбранных турбин и необязательный ID ревизии; после `POST` загружает результат по `id`, фильтрует точки просматриваемой турбины и показывает первые 24 или все 48 часов. `issued_at` без смещения — локальное время Казахстана UTC+5; `weather_run_at` и `valid_at` без смещения — UTC. Это текущий временной контракт; лучше перейти к ISO 8601 со смещением в обоих слоях при следующем изменении API.

Погодный выпуск ECMWF выбирает backend, а не браузер. Дата отсечения обучения задаётся при создании ревизии: по умолчанию исключается 31 января и всё позже, а для выпусков с 1 февраля можно исключать только февраль. Backend проверяет, что последняя обучающая запись строго раньше момента выпуска. В интерфейсе есть проверка количества часов и диапазона мощности. Open-Meteo не подтверждает момент фактической публикации выпуска; фиксированный запас около семи часов пока остаётся допущением.

## Проверка на ПК

Из корня запустить backend по `README.md`. В `frontend/` выполнить `npm ci`, `node --test tests/model.test.js`, `npm run build`, `npm run dev`. Открыть `http://127.0.0.1:5173`, выбрать 31 января 2026 года, запустить расчёт, переключить турбины и горизонты. Результат должен содержать 48 последовательных точек на турбину и архивный погодный выпуск раньше момента расчёта. Серверная версия не обновляется автоматически при merge `dev`.
