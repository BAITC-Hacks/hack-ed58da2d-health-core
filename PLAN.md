# План разработки на соревновательные 13:00–18:00

Это рабочий план по кейсу «Agentic AI для прогнозирования выработки ВЭС». Ветка `init/agentic-wind-forecast` общая для начальной интеграции. Оба участника регулярно отправляют собственные небольшие коммиты; перед совместной работой нужно договориться, кто меняет общие файлы, и делать `git pull --rebase` перед `git push`.

## Критерии готовности

1. Исходные измерения двух турбин импортированы без потери исходных значений и доступны для просмотра.
2. По ним построена модель почасовой нормализованной мощности. Валидация идёт строго по времени, не случайным перемешиванием.
3. Каждый прогноз использует архив отдельного погодного выпуска, опубликованного до момента расчёта. В результатах видны время выпуска и версия модели.
4. Для дат с 31 января по 28 февраля последовательно вычисляются прогнозы 1–48 часов; февральские прогнозные точки сохраняются и могут быть выгружены.
5. Весь цикл запускается из чистого окружения по README без личных аккаунтов участников. Если фактических значений февраля нет, это честно указано и метрика на них не выдумывается.

## 13:00–14:00 — основа и проверка данных

Андрей: проверить фактические границы CSV, пропуски и смысл нормализованной мощности; подключить Git, API, хранение и импорт. Настроить `.env.example`, зависимости, базовый smoke test. Михаил: выписать обязательные пункты кейса и сценарий жюри; подготовить первый экран и согласовать формат данных с API. Результат часа: репозиторий с запускаемым каркасом, каждый участник отправил свой содержательный коммит.

## 14:00–15:00 — модель и погодный источник

Андрей: обучить временной baseline, записать метрику на историческом holdout; проверить архив ECMWF по датам и обеим координатам; добавить таблицы/миграции для прогонов. Исследовать калибровку измеренного ветра турбины и прогнозного ветра 100 м. Михаил: экран исходных измерений с пагинацией и управление датой прогноза; состояния ожидания и ошибки. Результат: расчёт одного дня по реальному архивному погодному выпуску.

## 15:00–16:00 — сквозной агентный цикл

Андрей: оркестрация шагов `weather → prepare → predict → analyze → persist`; запись статуса и ошибок; идемпотентный повторный расчёт при новых измерениях/новом выпуске; последовательный запуск дат 31 января–28 февраля. Михаил: таблица и график прогноза для двух турбин, сведения об источнике и времени погодного выпуска; проверка API интеграции. Результат: один полный сквозной сценарий на экране и в БД.

## 16:00–17:00 — воспроизводимость и честная оценка

Андрей: автоматический smoke test, экспорт CSV прогнозов, проверка 48 точек на турбину и отсутствия прогноза погоды «из будущего»; миграции и запуск на PostgreSQL; локальный запуск с чистого окружения. Если организаторы предоставят февральские факты, посчитать MAE отдельно по горизонту и турбине; если нет — ограничиться временным holdout до февраля. Михаил: полировка сценария жюри, визуальное сравнение с историей, пояснение нормализованной шкалы и ограничений. Результат: повторяемый демонстрационный прогон.

## 17:00–18:00 — стабилизация и сдача

Андрей: проверить README по чистому запуску, зависимости, источник и лицензию данных, отсутствие секретов; smoke test сервера по SSH-туннелю; финальные коммиты и push до 18:00. Михаил: окончательная интеграция, демо, название и описание решения для формы сдачи; личный коммит и push до 18:00. Оба участника остаются на площадке и проверяют видимость удалённых коммитов. Кнопку «Сдать решение» нажимает участник команды после проверки.

## Приоритеты при нехватке времени

Сначала корректный архивный прогноз без утечки будущих данных и запуск по README. Затем полный прогон февраля и экспорт. Далее калибровка и улучшение модели, графики, автоматический пересчёт. Не заменять архив прогнозов фактической погодой задним числом и не заявлять февральскую точность без февральских фактов.
