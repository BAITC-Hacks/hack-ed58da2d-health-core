# WindSight — frontend аналитики ВЭС

Vue 3 + Vite. Запуск из этой папки: `npm ci`, затем `npm run dev`.
Открыть http://127.0.0.1:5173. Для сборки: `npm run build`.
Node.js 20.19+ или 22+. Внешние шрифты и CDN не нужны.

API по умолчанию: http://127.0.0.1:8000. Для другого адреса скопируйте `.env.example` в `.env` и измените `VITE_API_URL`; перезапустите Vite. Клиентские переменные публичны, не храните в них секреты.

Backend запускается по корневому README. Прогноз требует импортированных данных, обученной модели и доступа сервера к погодному источнику. Без backend доступен интерфейс с пустыми состояниями; графики не заполняются вымышленными данными.

## Проверка

1. Выберите 31.01.2026, запустите агента. Запрос создаёт 48-часовой прогноз двух турбин.
2. Переключите турбину: должно быть 48 точек. Переключите горизонт на 24: должно быть 24 точки этого же расчёта.
3. Переключите мощность / ветер / температуру. Наведение и ползунок выбирают час; точные числа доступны в таблице.
4. Экспортируйте CSV. Временные метки в CSV — UTC, в интерфейсе — UTC+5.
5. В источниках видны погодный выпуск, версия модели и отсутствующие метаданные. В истории можно открыть сохранённый запуск по ID.
6. Остановите API: новый запрос показывает ошибку и сохраняет предыдущий результат.

`node --test tests/model.test.js` проверяет границы времени, горизонты и диагностику пропусков.

## Границы текущего backend-контракта

Используются GET /health, POST /forecasts/{date}, GET /forecasts/{id}.
API не предоставляет batch-задачу февраля, промежуточные агентные события, исторический cutoff, координаты в ответе, время публикации прогноза или доверительные интервалы. Эти возможности не имитируются. Ежедневные выпуски пока запускаются по одному; история на экране ограничена текущей сессией, сохранённый результат можно открыть по ID.

В текущем backend naive `issued_at` означает UTC+5, naive `valid_at` и `weather_run_at` — UTC. Явный offset поддерживается и имеет приоритет. Сравнение времени инициализации погоды с выпуском ВЭС само по себе не доказывает отсутствие утечки будущих данных.

Реальный сквозной прогноз можно проверить только с подготовленной backend-моделью. Браузерные проверки на тестовом API не являются проверкой точности модели.
